# Document Validation System

## Project Overview

This project implements a document validation system designed to validate documents against tenant-specific business rules. Each tenant can have its own validation rules, such as maximum document size checks, required metadata field validation, and prohibited words detection.

The project follows an object-oriented approach with clear separation of responsibilities. Documents are represented by the `Document` entity, validation logic is implemented through independent rule classes, and the `DocumentValidator` coordinates the validation process using rules provided by the `TenantRuleProvider`. This design allows adding new validation rules or tenants without changing the existing validation flow.

The code structure follows SOLID principles, especially the Single Responsibility Principle and Dependency Inversion Principle. Validation rules are implemented as independent components, while the `DocumentValidator` depends on abstractions (`RuleProviderInterface`) rather than concrete implementations, making the system easier to extend and maintain.

## Technical Notes

The project uses strict dependency versions in `composer.json` to ensure a predictable and reproducible environment.

The application entry point is the `run()` function located in `demo.php`, which initializes the application and starts the validation process.

For demonstration purposes, the CLI execution flow is represented by `demo.php`. The demo data set used for validation scenarios is generated by the `buildDemoTenants()` function. It contains multiple tenants with different configurations and validation rules to demonstrate both successful and failed validation cases.

Automated tests are located separately and are executed through the dedicated `DocumentValidatorTest.php` file.
